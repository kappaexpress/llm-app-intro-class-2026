# 01. 悪いプロンプト vs 良いプロンプト

同じ目的でも、書き方ひとつで応答の質はまるで変わります。
ペアになっているプロンプトを順に試して、応答の違いを観察してください。

---

## 例1: メール作成

### 悪い版

```text
メール書いて
```

**期待される挙動**: 「どんなメールですか?」と聞き返されるか、無難で当たり障りのないテンプレが返ってくる。情報が足りなすぎて使えない。

### 良い版

```text
取引先の田中様宛に、来週月曜14時の打ち合わせを30分後ろ倒しに
してほしいというお願いメールを書いてください。

条件:
- 丁寧だが、かしこまりすぎないトーン
- 本文200字程度
- 件名も含めて出力する
```

**期待される挙動**: そのまま送れそうな完成度のメールが、件名つきで1回で出てくる。

---

## 例2: 文章要約

### 悪い版

```text
これ要約して

(長い記事を貼る)
```

**期待される挙動**: 長さもフォーマットも不定。箇条書きで来たり段落で来たりする。

### 良い版

```text
以下の記事を要約してください。

条件:
- 全体で150字以内
- 専門用語は避け、中学生にもわかる日本語で
- 最後に「ひとことで言うと」を1行で添える

記事:
(長い記事を貼る)
```

**期待される挙動**: 字数と読み手レベルが固定されているため、毎回同じ品質で揃った結果が出る。

---

## 例3: コードレビュー

### 悪い版

```text
このコードどう?

def add(a, b):
    return a+b
```

**期待される挙動**: 「特に問題なさそうです」程度の薄い感想で終わる。

### 良い版

```text
あなたは10年経験のあるPythonエンジニアです。
以下のコードを、可読性・型安全性・テスト容易性 の3観点で
レビューしてください。各観点ごとに 「指摘」と「改善コード例」を出してください。

def add(a, b):
    return a+b
```

**期待される挙動**: 型ヒントの欠如、docstring の不在、エッジケースのテスト案などが観点ごとに整理されて返ってくる。

---

## 例4: アイデア出し

### 悪い版

```text
新しいカフェのアイデア
```

**期待される挙動**: 既視感のあるアイデアが何個か出るだけで、深掘りされない。

### 良い版

```text
飲食業界のコンサルタントの観点から、
都内のオフィス街で、平日ランチタイムを狙った新しいカフェの
コンセプトを3案提案してください。

各案について以下を含めてください:
- コンセプト名(15字以内)
- ターゲット顧客像
- 他店との差別化ポイント
- 想定される客単価
```

**期待される挙動**: 案ごとに同じ構造で情報が揃い、比較検討しやすい。

---

## まとめ

良いプロンプトに共通している要素:

1. **誰として** 答えてほしいか(視点)
2. **何を** してほしいか(具体的なタスク)
3. **どんな制約** があるか(字数・トーン・観点)
4. **どんな形** で返してほしいか(出力フォーマット)

この4点を意識するだけで、応答の質が劇的に変わります。
