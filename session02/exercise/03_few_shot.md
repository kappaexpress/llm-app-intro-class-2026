# 03. Few-shot プロンプト

言葉で説明しにくいパターンも、**例を見せれば** LLMは真似できます。
分類・抽出・フォーマット統一などで特に効果的です。

---

## 例1: 感情分類 (Zero-shot vs Few-shot)

### Zero-shot 版(例なし)

```text
以下のレビューを ポジティブ / ネガティブ / 中立 に分類してください。

「料理は美味しかったが、待ち時間が長すぎた」
```

**期待される挙動**: 答えは返るが、「ポジティブ寄りの中立」「混合」など曖昧な判定をされることがある。

### Few-shot 版(例3つ)

```text
以下のレビューを ポジティブ / ネガティブ / 中立 のいずれかに分類してください。
分類ラベルだけを1語で答えてください。

例:
入力: 「最高でした、また来ます!」
出力: ポジティブ

入力: 「値段の割に普通でした」
出力: 中立

入力: 「店員の態度が悪かった、二度と行きません」
出力: ネガティブ

本番:
入力: 「料理は美味しかったが、待ち時間が長すぎた」
出力:
```

**期待される挙動**: 1単語のラベルだけが返ってくる。判定基準も例から推測してくれる。

## 例2: フォーマット統一(住所抽出)

```text
以下の文章から「氏名」と「都道府県」を抽出して、決まった形式で出力してください。

例:
入力: 「山田花子さん(東京都在住)が来店しました」
出力: 氏名=山田花子, 都道府県=東京都

入力: 「大阪府の鈴木一郎様からお問い合わせがありました」
出力: 氏名=鈴木一郎, 都道府県=大阪府

入力: 「佐藤次郎(神奈川県)が応募してきました」
出力: 氏名=佐藤次郎, 都道府県=神奈川県

本番:
入力: 「先日、福岡県の田中三郎さんが商品をご購入されました」
出力:
```

**期待される挙動**: `氏名=田中三郎, 都道府県=福岡県` という決まった形式で返ってくる。これがあると後続のプログラム処理で扱いやすい。

## 例3: 文体変換(カジュアル → ビジネス)

```text
カジュアルな文章をビジネスメール風に書き換えてください。

例:
入力: 「明日の会議、ちょっと無理かも」
出力: 「明日の会議の出席が難しい状況です。大変申し訳ございません」

入力: 「資料できたよ、見て」
出力: 「資料が完成いたしましたので、ご確認をお願いいたします」

入力: 「あの件どうなった?」
出力: 「先日の件につきまして、進捗をご共有いただけますでしょうか」

本番:
入力: 「来週飲みに行かない?」
出力:
```

**期待される挙動**: 「来週、お食事でもいかがでしょうか」のようにビジネス文体に変換される。スタイルが例によって完全に固定される。

## 例4: 命名規則の統一(ファイル名生成)

```text
記事タイトルから、ケバブケースの英語ファイル名を生成してください。

例:
入力: 「Pythonで作るWebアプリ入門」
出力: python-web-app-introduction

入力: 「初心者のためのGit講座」
出力: git-course-for-beginners

入力: 「データベース設計の基礎」
出力: database-design-basics

本番:
入力: 「機械学習を使った画像認識入門」
出力:
```

**期待される挙動**: 例と同じ命名規則(小文字・ハイフン区切り・英訳)で返ってくる。

---

## Few-shot のコツ

1. **例は2〜5個** が目安(多すぎても精度は頭打ち、コストだけ増える)
2. **多様な例** を入れる(似た例ばかりだと偏りが出る)
3. **本番の入力と同じ形式** で例を書く
4. **「出力:」のあとを空にして渡す** と、続きを生成しやすくなる
5. **ラベル名・フィールド名は揃える**(表記揺れがあると LLM も揺れる)

---

## 試してみよう

例4のプロンプトで、最後の「本番」の入力を自分で別の記事タイトルに差し替えて投げてみてください。

例えば:

- 「JavaScriptで作るゲーム開発入門」
- 「ChatGPT活用術 仕事編」
- 「美味しいコーヒーの淹れ方」

例のパターンに沿って、ちゃんと命名規則を守った出力になるか確認しましょう。
