# 講師用ガイド

## 構成と前提

座学8回（各90分、短い演習を含む）と制作5回です。
Web基礎授業の技術構成を継続し、LLMとの通信と外部知識の扱いへ焦点を移します。
第1回の完成品観察で到達点を共有し、第2回以降で機能を分けて実装します。
各回の解答と進行はsessionXX/teacher.md、時間配分はslides.mdにあります。

## 開講前

1. Codespacesを新規作成し、依存関係とポート8000番の起動を確認。
2. 学生ごとのAPI利用方法、予算、キーの管理者を決める。講師の生のキーを共有しない。
3. gpt-6-lunaとtext-embedding-3-smallの利用権限・料金・規約を確認。
4. APIモードで資料あり/なし、意味検索、Function Callingをそれぞれ実行。
5. 講師の実行結果を、秘密を除いて記録し、障害時の観察用に準備。
6. forkした各学生のポートをPrivateのまま使用する。

教材には実APIで取得した応答・Embeddingの保存データは含みません。
APIが使えないときはデモで処理の流れを学び、品質の評価は講師の実演記録を使います。

## 平易なコードの方針

- 独自クラスを避け、通常の関数・if・for・辞書・リストを中心にする。
- DB接続、SQL、commit、closeを見える形で書く。
- LangChain等のRAGフレームワーク、ORM、フロントエンドフレームワークは導入しない。
- SDKが扱うモデルのクラスと、入力検証のPydanticだけは利用する。
- 完成版は役割ごとにファイルを分ける。前半の回から全ファイルを読ませない。

## 完成版から各回への展開

最初にsample-appを作成し、scripts/build_sessions.pyでコピーしました。
各回のsolutionは未習機能をソースから削除、exerciseはその回の中心部分をコメントアウトします。
実行時のSTAGEフラグや、他の回をimportする仕組みは使っていません。

| 回 | 完成版から削るもの | 演習で空ける部分 |
|---|---|---|
| 1 | なし。観察のみ | ワークシート |
| 2 | Web、DB、検索、ツール | Responses API呼び出し |
| 3 | DB、資料、検索、ツール、回数制限 | fetchによるPOST |
| 4 | 検索、ツール、回数制限 | 根拠を限定する指示文 |
| 5 | ベクトル、ツール、回数制限 | 単語一致のスコア |
| 6 | ツール、回数制限 | 内積と長さの計算 |
| 7 | 回数制限 | 条件付きSELECT |
| 8 | なし | 回数制限の条件 |

講師が再生成する場合、`python scripts/build_sessions.py --replace` を使います。
**exercise、solution、your-appのコード・ワークシートを上書きするため、学生は実行しません。**
先にGitへ保存し、必要な資料や学生の変更を復元してください。README・ワークシートは配布版のGitから戻せます。

## 評価と安全性

共通質問はevaluation-cases.jsonです。IDよりファイル名と見出しを正解根拠にします。
検索の成功、回答の正確さ、引用の支持、適切な保留を分けます。
複数回の評価では結果をそろえるため、資料と設定を固定します。
攻撃用資料はテスト時だけ追加し、終了後に削除・再登録します。

この教材に認証や利用者ごとの資料権限はありません。公開サービスとして配布しません。
ポートPrivateでも、学生自身のAPI予算管理は別に行います。
プロセスの質問回数制限は再起動でリセットされ、EmbeddingやCLIの費用は止めません。

## 制作

必須は外部資料の検索、根拠表示、保留、評価です。
Function Callingやベクトル検索は任意。題材の内容と学生の進度で選びます。
完成品の見た目以上に、データの流れと失敗原因を説明できるかを見ます。
