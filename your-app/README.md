# オリジナルアプリ制作（第9〜13回）

完成版sample-appのコピーです。このディレクトリを自分の題材へ改造します。

```bash
# リポジトリのルートから
source .venv/bin/activate
cd your-app
python init_db.py
python build_index.py
python main.py
```

API設定は[ルートの手順](../README.md#apiを使う設定)を参照。生成はgpt-6-lunaを使います。
資料の変更後はサーバーを止めてinit_db.py、意味検索ならbuild_index.pyも実行します。

## 5回の進め方

| 回 | 作業 | 提出・確認 |
|---|---|---|
| 9 | 利用者、困りごと、資料の利用条件を決める | design.md、資料、評価質問10問 |
| 10 | 自分の資料で検索から回答まで動かす | 小さくても一通り動くデモ |
| 11 | 根拠表示、保留、待機・エラー表示を整える | 根拠と異常系の動作 |
| 12 | 他の学生に試してもらい1つずつ改善 | evaluation.md、改善前後 |
| 13 | 仕組み、結果、限界を説明する | デモ、コード、設計・評価記録 |

## 必須条件

- 自分で選んだ外部資料を検索してLLMへ渡す。
- 出典を確認できる。
- 根拠不足への対応を設計する。
- 10問以上を評価する。少なくとも資料にない質問、言い換え、複数根拠を含める。
- APIキーを漏らさず、失敗時の表示と利用制限を維持する。

ベクトル検索・Function Callingは任意。題材に不要な方式は画面とAPIの両方から削除できます。
初めはdata/、画面の名称、指示文を変更し、動作確認してから機能を追加します。

## 題材例

部活の案内、施設の利用方法、製品マニュアル、ゲームのルール、自分の学習ノート。
利用できる資料を選び、実在の学生の成績などを送信しないでください。

## 発表

目安5分＋質疑。対象者と課題、通常のデモ、根拠不足のデモ、処理の説明、
評価と改善前後、残る問題を示します。API障害に備え、秘密を含まない実行記録も用意します。

採点：課題と知識源20、動作25、根拠・保留20、評価改善25、説明10。
