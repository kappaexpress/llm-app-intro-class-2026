# 第6回 演習: チャットUI + マルチターン会話

ブラウザで動くチャット画面に、AIが「前の発言を覚えている」状態を実装する。
ただしこの回の時点では **DB保存はまだ無し**。会話履歴はフロント側
(ブラウザのメモリ)にだけ持つため、リロードすると消える。

## このバージョンの仕様

- 1会話のみ(会話の切り替え機能なし、サイドバーなし)
- 会話履歴(`messages` 配列)はフロント側で保持
- 送信のたびにフロントが `messages` 全体をサーバに送る
- サーバは system プロンプトを先頭に差し込んで OpenAI に丸投げするだけ
- リロードすると会話は消える(履歴の永続化は第7回)

## 起動手順

### 1. APIキーをシェルに export する

講師から配布された OpenAI API キーを環境変数にセットする。

```bash
export OPENAI_API_KEY=sk-...
```

`export` は **そのシェルにだけ** 有効。ターミナルを開き直したら毎回必要。
キーは絶対にコードにベタ書きしたり Git にコミットしたりしないこと。

### 2. 依存パッケージのインストール(初回のみ)

リポジトリのルートに `requirements.txt` がある。

```bash
pip install -r requirements.txt
```

### 3. サーバを起動する

```bash
cd session06/exercise
python main.py
```

`http://localhost:8000` をブラウザで開く。

## 動作確認

### A) マルチターン会話ができることを確認する

1. 「私の名前は田中です」と送る
2. AIが返答してきたら「私の名前は何でしたか?」と聞いてみる
3. 「田中です」のように **覚えていることを確認**

これができていれば、フロントが `messages` 配列に履歴を積んで毎回まるごと
送れている証拠。サーバ側は履歴を持っていないのに「覚えている」ように
見えるのがポイント。

### B) リロードで会話が消えることを確認する

1. しばらく会話を続ける
2. ブラウザをリロード(Ctrl+R / Cmd+R)
3. **画面が空になり、過去の会話も消えている** ことを確認

これは「履歴をフロント側だけで持っている」ためで、リロードすると
JavaScript の `messages` 変数が初期化されてしまう。
これを直すのが第7回(SQLite永続化)。

### C) DevTools で `messages` が長くなる様子を観察する

これが今回のコア体験。**毎回まるごと送る** ことを目で見て理解する。

1. F12(または右クリック → 検証)で DevTools を開く
2. **Network タブ** を選び、`Fetch/XHR` でフィルタする
3. 何回かやり取りをする
4. リストに並ぶ `chat`(POST /api/chat)を 1つ目→2つ目→3つ目... の順にクリック
5. 「Payload」(または「ペイロード」「リクエスト」)を見ると、毎回送られている
   `messages` 配列がどんどん長くなっていくのが見える

さらに **Console タブ** で次のコマンドを叩くと、今のフロント側の履歴を
直接覗ける:

```javascript
__debug.show();
```

何往復もしたあと、`messages.length` が増え続け、配列の中身が
過去のやり取りを全部含んでいることを確認しよう。

### D) コンテキストウィンドウの直感

`gpt-5.4-nano` のコンテキストウィンドウは **400Kトークン**。
日本語ざっくり 1文字 ≒ 1〜2トークン と思えば、約 数十万文字までは
1回のリクエストに乗る。普通のチャットでは当面気にする必要はないが、
**長い文章を貼り続けると消費は加速する** ことだけ覚えておく。

## トラブルシューティング

- **`openai.AuthenticationError`**: `OPENAI_API_KEY` が正しく export されていない
  → 同じシェルで `echo $OPENAI_API_KEY` を実行して値が出るか確認
- **`Address already in use`**: 8000番ポートが既に使われている
  → 前回起動したサーバが残っていないか確認
- **画面が真っ白**: `static/` フォルダの位置がおかしい可能性
  → `session06/exercise/` ディレクトリで `python main.py` を実行しているか確認
